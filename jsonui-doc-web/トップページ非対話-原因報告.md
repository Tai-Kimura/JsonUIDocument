# 障害報告書：トップページが本番ビルドで非対話（リンク/ボタンが無反応）

**日付:** 2026-06-18
**重大度:** 高（本番ビルドでトップページが操作不能）
**結論:** **jsonui-cli 本体のバグではない。** 本リポジトリのトップページ用 hook ラッパ1ファイルの1行バグ。
**状態:** 原因特定済み・修正を dev / 本番静的エクスポート双方で検証済み。

---

## 1. 要約（TL;DR）

`jsonui-doc-web/src/hooks/useHomeViewModel.ts` の post-mount `mountLanguage()` 用 `useEffect` の
依存配列が `}, [result])` になっている。`result` は**毎レンダリングで新規生成されるオブジェクト**
（生成 hook が毎回 `{ data, viewModel, setVars }` を新しいリテラルで返すため）なので、effect が
毎レンダリングで再発火する。`mountLanguage()` は `onAppear()` を呼び、`onAppear()` は `setState`
を行う → 再レンダリング → `result` が新オブジェクト → effect 再発火 → **無限レンダリングループ**
（"Maximum update depth exceeded"）。React が描画を打ち切り、ハイドレーションが完了せず、本番の
静的エクスポートでトップページが非対話のままになる。

**他41個の `mountLanguage` ラッパは全て `}, [])` を使っており、トップページのラッパだけが例外。**
修正は他に合わせるだけ。

```diff
-  }, [result]);
+  }, []);
```

---

## 2. 症状

- ページは表示される（SSR の HTML は正しい）が、**リンク/ボタンをクリックしても何も起きない**。
- 本番ビルドでは目に見えるコンソールエラーが出ない（React 19 がループを打ち切った後に握りつぶす）。
- `next dev` ではコンソールに以下が大量に出る:
  `Maximum update depth exceeded. This can happen when a component calls setState inside useEffect…`

## 3. 切り分け（除外した仮説と根拠）

| 仮説 | 検証 | 結果 |
|---|---|---|
| AWS / CloudFront 配信が原因 | 同じ `out/` を `python -m http.server` でローカル配信 | **本番と完全に同一** → 配信は無関係 |
| Turbopack（バンドラ）が原因 | `next build --webpack` で再ビルド | **完全に同一** → バンドラは無関係 |
| ハンドラ未配線 | ボタンの React props を読む | `onClick` = `() => this.navigate("/learn/installation")`（正しい） |
| ハンドラ/router が壊れている | `onClick` を直接呼ぶ | エラー無し・しかし `history.pushState` が**呼ばれない** → React が反映していない |
| ハイドレーションが有効化していない | `next dev` のコンソール | **"Maximum update depth exceeded"** ループ → これが根本原因 |

## 4. 根本原因

`src/hooks/useHomeViewModel.ts`:

```ts
const result = useGeneratedHomeViewModel(router); // 毎レンダリングで新規オブジェクトを返す
useEffect(() => {
  result.viewModel?.mountLanguage?.();            // → onAppear() → updateData() → setState
  // …言語変更イベントの購読…
}, [result]);                                     // ← 毎レンダリングで変化 → effect が無限に再発火
```

- `result` の参照が毎レンダリングで変わる（生成 hook が新しい `{ data, viewModel, setVars }` を返す）。
- `mountLanguage()` → `HomeViewModel.onAppear()` → `updateData()` → `_setData()`（React の setState）。
- setState → 再レンダリング → 新 `result` → `[result]` 変化 → effect 発火 → setState → … **無限ループ**。
- React が暴走レンダリングを中断し、クライアントツリーが対話可能にならない → クリックが死ぬ。

影響は**トップページのみ**（42個の `mountLanguage` ラッパ中1個）。他41個は `[]` 依存で正常。

## 5. 修正（検証済み）

他のラッパに合わせ、マウント時に1回だけ走らせる:

```diff
// jsonui-doc-web/src/hooks/useHomeViewModel.ts
-  }, [result]);
+  }, []);
```

（`[result.viewModel]` でも可。`viewModel` は `useRef` の安定値。ただし他41個と揃え、かつ
「マウント後1回」が意図なので `[]` が適切。）

### 検証結果

| ビルド | 修正前 | 修正後 |
|---|---|---|
| `next dev` | "Maximum update depth exceeded" が大量発生 | エラー無し。CTA クリックで `/learn/installation` に遷移 |
| `next build`（静的エクスポート） | CTA クリックで遷移せず | CTA クリックで**遷移**（`history.pushState` 発火） |

## 6. jsonui-cli への任意の堅牢化提案（必須ではない）

生成 hook `src/generated/hooks/use*ViewModel.ts` は非メモ化のオブジェクト
（`return { data, viewModel, setVars }`）を返す。これを依存配列に丸ごと入れると毎レンダリングで
再発火する。返り値を `useMemo` でメモ化しておけば、この種のミスが無害化される。ただし今回の
実バグは本リポジトリのラッパ側のみ。

## 7. 補足：今回の本番化で初めて顕在化した理由

`next dev`（開発サーバ）はループのエラーを出しつつも動いて見える場面があり、見落とされやすい。
今回の AWS デプロイで初めて `next build`（`output: export` の本番静的エクスポート）を通したため、
ハイドレーション破綻が「非対話」という形で顕在化した。

## 8. 調査に使った再現手順

```sh
# 本番ビルドをローカル配信して挙動を確認（AWSと同一であることの確認）
cd jsonui-doc-web && npm run build
python3 -m http.server 8769 --directory out
# → / を開き、ヒーローCTA をクリック。修正前は無反応、修正後は /learn/installation へ遷移。

# 開発サーバでは修正前に無限ループのエラーが出る（根拠）
npx next dev -p 3111
# コンソール: "Maximum update depth exceeded …"
```
